# Scaling Law 总结版

# 需求

- 已经训练了一个 10b 模型，想知道训练一个 100b 模型，大概性能能够提升到多少？

- 部门已经收集到了 1T 的数据，想知道能训练一个多大的模型？

- 计划训练一个 100B 的模型，想知道至少需要多大的数据？

- 准备 1 个月后开发布会，给的资源是 100 张 A100，大概能训练出啥性能的模型？

- 准备 1 个月后开发布会，给的资源是 100 张 A100，应该用多少数据训多大的模型效果最好？最划算？



上述是几个非常典型的实际需求，需求复杂度也是逐步提升。Scaling Law 实验就是为了基于大量小成本的实验，然后建模得到模型性能与参数量，训练总 token 数和计算成本之间的关系，从而在开始训练超大模型前外推解决上述实际问题，节省人力物力。

# 前言

目前 Scaling Law 主要是建模模型性能\(验证集 loss 或者评测指标\) 与模型参数量，训练总 token 数和计算成本之间的关系。

除了上述主流的 Scaling Law，一些机构也对训练中的核心超参例如 batch size 和 lr 进行建模，也有一些论文会对数据配比进行建模，这些都有比较大的参考价值。

但是由于这些参数之间的相互依赖的，超参也是相互耦合，因此现在大家做的 Scaling Law 实验可能都是相对片面的结果\(冰山一角\)，迫切需要一个能够全面建模的 Scaling Law 实践。



在正式分析 scaling law 之前，需要对一些概念有一定了解。

# 核心概念

## C=6ND

- **L**：验证集上 ce loss 或者验证集上 ppl 分数，用于表示预训练后的模型性能。 Loss 越小就认为性能越好

- **D**：训练完成消耗的总 token 数

- **N**：模型可训练参数量，**一般是不包括 embeding 层的参数量**\(原因是本身占比不大，并且在 tie\_embeding 情况下会和 output layer 层共享参数，有点不方便算\)

- **C**：计算代价，通常是一次完整实验的 FLOPs



首先要明确，C 和 ND 之间是固定关系的，对于给定的架构， C N D 之间的关系是可以提前算出来的，不需要进行实验，以 openai 论文中的标准的 Decoder\-Only Transformer 为例

- 忽略掉了 embeding 层和 output 层的参数

- n\_ctx 是上下文长度，假设是 1024，由于这个模型还是绝对位置编码，并不是现在主流的旋转位置编码，因此位置编码是有可学习参数的

- 但是由于序列长度不是很大，计算量可以省略

所以一般设置下假设是 1B 模型，那么就是 20 层，d\_model 是 2048，对应的 FLOPs 也可以算出来

C\_forward= 2\* N，加上两倍的 backward 成本，那么每个 token 大概就是 C = 6N，考虑整个数据集则得到

C 约等于 6 \* N \* D  

\# N 是参数量，D 是训练总token 量，C 表示训练总的计算代价，且不考虑 embeding 层

通过推导，我们就得到了 C=6ND 这个公式。

注意上述的公式针对特定的结构计算的，不同的设置和架构会有点区别，如果想特别精确，那最好基于自己设计的模型重新计算，后续才会得到更准的 scaling law 公式。

上述公式非常容易理解，计算代价与模型参数量、训练总 token 数成正比。也就是说给定了其中两个参数，其实第三个参数就已经固定了。

## 幂律关系

幂律是一种数学方程，用于描述一个特定量随另一个量的幂变化的关系。在幂律中，一个量的变化与另一个量的变化的幂\(指数\)成比例。

幂律方程 y = bx^a 表示 y 的变化量与 x 的变化量的 a 次方成正比。如果 a 是 2，那么当 x 翻倍时，y 将增加 4 倍。现实世界中的一个例子是圆的面积与半径的关系。

幂律 y = bx^a。取两边的对数,幂律变为 log\(y\) = alog\(x\) \+ log\(b\)。这是一个线性方程\(在对数空间中\),其中 a 是斜率,log\(b\) 是 y 轴截距。因此，幂律关系在对数\-对数图上会呈现为一条直线，直线的斜率对应于幂律中的指数。

第二条曲线是对方程两边取 log\-log 绘制的结果。这就是所谓的幂律关系，实验表明 scaling law for llm 也是幂率关系。

## 实验 1：学习率调度策略无关

在实验中发现：收敛的结果在很大程度上与学习率调度策略无关。除非另有说明，我们数据中包含的所有训练运行都使用具有 3000 步线性预热的学习率计划，然后是余弦衰减为零。

![image\.png](图片和附件/image_38.png)

只要学习率不是太小并且不会太快衰减，性能就不会强烈依赖于学习率。运行到运行的变化在损失中的 0\.05 级别。

- 在不考虑计算成本和数据量不够情况下也就是计算成本和数据总量不做任何限制，不管多大的模型必须要确保已经收敛，如果模型已经出现过拟合现象\(理论上只有数据足够多就不能过拟合\)，那么也应该记录的过拟合前的 val loss，也就是始终记录的是最好值。

- 思路 scaling law 曲线的适用性，这个曲线是否可以外推到 100b 甚至 1000b 模型上。从目前 llama3 400b 模型来看，至少这个量级是没有问题的，因此现阶段不用担心 scaling law 的外推性

- 左图每一条线都代表在给定模型参数量情况下，不断增加数据量，所能达到的收敛 loss。可以预见在给定模型参数量情况下，一直加数据，必然不会过拟合，val loss 开始会快速下降，后续趋于平稳或者下降非常缓慢。虽然继续加数据性能肯定会涨，但是此时就不是本文追求的性能\-效率最优点。比如在固定参数量情况下，你加了 5 倍数据， val loss 只降了 0\.01，那么就划不来了。

- 同样的，如果训练总 token 数固定，理论上不断加大模型性能会越来越好，但是也面临错过性能\-效率最优点。比如在固定数据量情况下，你加了 5 倍模型， val loss 只降了 0\.01，那么就也划不来了，而且其实还可以出现过拟合现象。

要明白：Scaling law 追求的是性能\-效率或者性能\-代价最优平衡点，而不是一味追求性能。



从左图还能得到一个重要结论： 越大的模型在消耗更少数据情况下就可以收敛到小模型大数据同样甚至更好的性能\(画一条水平线表示相同 loss水平，可以发现越大的模型越早达到这个 loss\)。这指导我们：在给定计算代价情况下或者说训练时间下\(虽然总的训练成本没有变，但是需要的高质量数据少了，相当于成本更低了\)，尽量选择更大的模型，训练收益才是最高。

![image\.png](图片和附件/image_33.png)

并且我们也知道了：要达到性能\-效率最优平衡点，我们要同时缩放训练总 token 和模型参数量，不能单一缩放。

从上述公式可以看出：**模型缩放比例应该比数据规模缩放比例大一点，每当我们增加模型大小 8x 时，我们只需要将数据增加大约 5x。 **

**但是不同的论文有不同的看法，这个缩放比是一个关键。而且我们通俗理解肯定和数据质量和分布有关系的，所以这个缩放比需要基于自己的数据质量来确定，无法直接套用。**



有了上述联合公式，其实很多需求都能直接解决了

- 部门已经收集到了 1T 的数据，想知道能训练一个多大的模型？ **只需要把 D 带入到公式，然后求在 L 最小的情况下所对应的模型参数量**

- 准备 1 个月后开发布会，给的资源是 100 张 A100，应该用多少数据训多大的模型效果最好？最划算？ **只需要先计算出 1 个月\+ 100 张 A 100 的 FLOPs 是多少，然后找到最小的 val loss 是多少，然后利用这个 val loss 找到最佳的模型参数量/训练总 token 数。实际操作上可能存在多组参数符合需求，此时可以再从训练速度和推理速度角度考虑最佳值。**



上述曲线也可以反推出在当前模型参数量情况下，最少需要多少数据才不会过拟合\(可以解决：计划训练一个 10B 的模型，想知道至少需要多大的数据？\)。分母表示在数据量无限情况理论的收敛 loss，在无限数据集下我们认为模型一定不会过拟合，当左边的值越大表示过拟合越严重，等于0 表示完美情况。假设**误差在 0\.02**，那么**可以算出最小的 D 是多少。**

# DeepMind Scaling Laws

Training Compute\-Optimal Large Language Models

https://arxiv\.org/pdf/2203\.15556

也叫作 Chinchilla Scaling Laws。**这个 scaling law 应用更广泛，因为他的做法更直接，更直观，可操作性更强。**

同时相比于 openai 结论，一个重要区别是他：对于计算最优训练，模型大小和训练令牌的数量应该相等地缩放。

## 概述

在实践中，分配的训练计算预算通常是预先知道的：**有多少卡可用，以及我们想要使用它们的时间**。我们需要的是给定预算下最佳模型大小和训练 token 总数。这是一个更加实际的问题，因此本文的 Scaling Laws 才是实际上用的最多的，包括 llama3 等都是用的这套做法。

给定一个固定的 FLOPs 预算，一个权衡模型大小和训练令牌的数量应该如何？

![image\.png](图片和附件/image_42.png)

N 是模型参数量，D 是训练总 token 数，C 是计算代码 FLOPs。

具体实验上作者根据超过 400 个模型的损失经验估计这些函数，范围从 70M 到超过 16B 参数，并在 5B 到超过 400B 标记上进行训练——**每个模型配置针对几种不同的训练范围进行训练，确保严谨**。

基于估计的计算最优边界，我们预测对于用于训练 Gopher 的计算预算，最优模型应该小 4 倍，同时在 4 倍的标记上进行训练。我们通过训练一个更通用的 **70B** 模型（称为 Chinchilla）来验证这一点，该模型在 1\.4 万亿 个令牌上。Chinchilla 不仅优于其更大的对应物 Gopher，而且其减小的模型大小大大降低了推理成本，极大地促进了较小硬件上的下游使用。

![image\.png](图片和附件/image_21.png)

从现在眼光来看，这些模型其实依然还是欠训练的，数据量太少了。



有一个注意点： openai 做 scaling law 实验时候，是不管多大模型，按最大步数=25万来设置 cosine schedule，最终decay 到零来实验的。如果模型比较大提前收敛了，则直接停止，也就是不一定真的训练完成。这可能会有问题

![image\.png](图片和附件/image_25.png)

如果设置为 25w 步，但是实际上只训练了 1w 步，那么 lr 实际上偏高，此时性能并不是最优的\(虽然看起来收敛了\)，可能会影响后续结论\(高估训练步数超过 25% 性能会影响很大\)，本文作者觉得该训到多少 step，cosine schedule 衰减的最低点就应该止步于多少 step，也就是说不同的训练 token 总数，要配备不同的 lr 学习率调度策略。不应该设置 step =25w，然后训练一半就停掉，这个做法会影响后面结论。



为了进行合理的 scaling law，作者一共提出了 3 种办法。在所有三个方法中，我们首先训练一系列同时改变模型大小和训练令牌数量的模型，并使用生成的训练曲线来拟合它们应该如何缩放的经验估计公式，同时依然假设计算和模型大小之间存在幂律关系。

## Approach 1: Fix model sizes and vary number of training tokens

![image\.png](图片和附件/image_35.png)

- 对于每个固定参数量的模型，我们训练了 4 个不同参数组合的模型，每个具体模型使用不同的 token 数进行训练，不同的 token 数要匹配不同的学习率策略，min lr 要衰减到 0\.1 倍，token 总数可能差距 16x，也就是说**每个参数的模型一共有 16条学习曲线，也就是每个参数模型有 16 个点**

- 以左图的黄色 10b 模型曲线为例，实际上应该是 16 个 loss 点\(可以拟合出一条平滑曲线\)，每个点代表一次实验，表示在当前计算代价情况下，训练特定 token 数所得到的训练 loss，可以发现如果训练成本越小但是模型参数量一定，那么训练 loss 必然越大；对于 10b 和 5b 模型，在计算代价一样但是比较少情况下，10b 模型训练的 token 数少一半，loss 也大一些，但是如果训练代价多一点，那么 10b 模型就和 5b 模型 loss 一样了，可以预计，如果训练代价持续增加，那么 10b 模型性能必然好于 5b 模型

- 上述大量的曲线就可以构造左图，对这些曲线计算包偌，就可以得到上图中的灰色曲线。这条曲线就表示在固定FLOPs 的条件下，对应的最小 Training loss

- 然后利用这条灰色曲线，我们可以得到两个非常有价值的曲线，第一个是在给定计算代价情况下，最优的模型参数量\(也就是在给定计算代价情况下，哪些尺寸的模型达到了最小 loss\)

- 同样的，我们可以得到在给定计算代价情况下，最优的训练 token 数\(也就是在给定计算代价情况下，哪些 token 总数达到了最小 loss\)

- 由于这个关系是幂率曲线，所以可以很容易计算出公式。有了这两个公式就可以解决问题了

# Dataset Scaling laws

RegMix: Data Mixture as Regression for Language Model Pre\-training

https://arxiv\.org/abs/2407\.01492

## 概述

大型语言模型预训练中的数据配比对性能有显著影响，但如何确定有效的配比仍不明确。

论文提出 REGMIX，通过将数据配比问题形式化为回归任务，自动识别高性能的数据配比。

REGMIX包括使用多种数据配比训练一组小型模型，并拟合一个回归模型来预测给定各自配比的模型的性能。利用拟合的回归模型，外推得到排名最高的配比，并使用它来训练一个大规模模型。

为了实证验证 REGMIX，论文训练了512个具有1M参数的模型，用于1B个不同配比的token，以拟合回归模型并找到最佳配比。使用这种配比，论文训练了一个1B参数的模型，用于25B个token（即比之前大1000倍，长25倍\)

论文还发现：

- 数据配比显著影响下游性能，导致单任务性能差异高达14\.6%；

- 通用网络语料库（如CommonCrawl），而非维基百科，与下游任务性能提升的正相关性最强；

- 领域间的交互复杂且常常与直觉相悖，突显了像REGMIX这样的自动化方法的必要性；

- 数据配比也可以应用到 scaling law 中，实现自动化



一共包括 4 个步骤：

- 生成随机数据配比并在此基础上训练小规模代理模型

- 使用表1：Pile数据集概览，其中因版权问题不再可用的数据集以灰色标记。在论文的实验中，论文使用可获得的17 个领域来研究语言模型预训练的数据配比作为特征，拟合一个线性回归模型

- 在更大规模上模拟数据配比空间，并利用回归模型识别目标值的最佳配比

- 使用模拟的最佳数据配比训练一个大规模模型

https://arxiv\.org/pdf/2407\.13623v2

## 模型深度是一个双刃剑

根据回归系数，层数对模型性能的影响最大。这是直观的，因为增加模型深度可以快速引入更多的非线性。然而，与scaling law 的理想预测不同，在实践中，层深度不是一切。深度模型训练的不稳定性阻碍了开发人员增加模型深度。如果训练基础设施具有计算精度问题（不幸的是很常见），深度模型的质量将严重损坏。

![image\.png](图片和附件/image_14.png)

上图显示了不同精度系数 γ 下的预测性能。在这里，我们将隐藏维度设置为 8192，FFN 大小设置为 28672。当训练基础设施具有良好的精度（γ = 1 可以通过领先公司实现）时，可以在不影响其性能的情况下训练超过 100 层的模型。不幸的是，如果精度不令人满意，预测性能会迅速衰减，这与工业中常见的实际经验一致。

此外，在相同的尺寸下，更深的模型通常具有较低的推理速度、训练速度和更大的KV缓存内存消耗。因此，如果开发人员更关注推理效率，或者对训练稳定性和精度没有信心，建议使用相对较浅的模型结构来降低不良精度的负面影响\(但是从这里来看，应该要到 40 层以上才有差别\)。

## 隐藏大小（有时）比 FFN 大小更重要

再次看看公式

![image\.png](图片和附件/image_36.png)

w1 = 13\.95018, w2 = 0\.23072, w3 = −0\.48523, w4 = 5\.39802, b = 9\.19541

w3 居然是负数。这说明如果模型是从头开始训练的，而不是从另一个模型扩展，那么最好使用相对较大的 hidden size 而不是 FFN 大小，这可能是因为大型 FFN 矩阵中参数的高度冗余。

然而，性能与 FFN 大小没有简单的负相关，因为它有助于控制不稳定的折扣 u。例如，Llama 405B \(3\.25\) 和 Mistral Large \(2\.33\) 中的 FFN 大小与隐藏大小h 的比率不是太大。这与我们自己的实践的实验结果非常一致。

然而，由于推理成本和模型训练的精度的限制，增加 FFN 的大小可能是一个折衷方案。因此，为LLM设计人员选择适度的 FFN 大小可能是可行的。

## 主流注意力架构似乎具有相似的性能

标准注意力架构有许多不同的变体，例如 GQA  和 MLA 。FFN的设计也从 bottleneck network 变为GLU。然而，我们假设，鉴于对性能定律的准确预测，它们可能具有相似的性能，尽管它们在实践中可能具有较小的性能差距。例如，根据 Gemma 2 报告，GQA 可能具有类似于 MHA 的性能。这表明我们仍然找不到“捷径”来显着提高基于 Transformer 的模型在相同但足够的计算能力下的性能。

## 顶级玩家具有相似的数据质量

数据质量和分布通常在很大程度上影响模型质量。然而，即使性能定律没有考虑数据质量和分布，预测精度仍然令人满意。这意味着**顶级LLM玩家可能具有相似的数据质量和分布\(尽管某些语言的比例可能会增加\)。**

所有主流 llm 通常使用书籍、论文、新闻文章、考试练习和代码库等来源。还共享一些常见的数据过滤和处理技术。这些原因导致不同组织使用的数据的固有同质性。一些领先的组织可能比竞争对手拥有明显更高和更高质量的数据。这将使超过性能定律的预测成为可能。

另一方面，我们需要承认知识密集型数据（例如考试问题）的影响。与常见的网页和书籍相比，这些形式的数据与 MMLU 评估更相关，对这些知识密集型数据进行训练可能会导致 MMLU 分数的增加。这解释了为什么第一代 Llama 的性能远低于预测。然而，我们可以看到更大的模型可能会缩小这一差距，如 Llama 65B、Text\-Davinci、Gopher 和 PaLM 所示。此外，我们可以看到大多数中文增强模型比预测表现更好。这可能是因为中文模型数据混合物中考试和练习数据的比例明显更高。

## MoE 很有前景，但难以训练

根据我们的分析，MoE 模型可以以更少的训练和推理成本与更大的密集模型实现相当的性能。此外，由于 FFN 大小的缩小，Deepseek V2 和 Qwen 57B\-A14B 等细粒度 MoE 可能比粗粒度 MoE 略有优势。基于我们的性能规律，设计者可以根据 MoE 模型的要求灵活调整配置。然而，基于moe的LLM的成功案例数量有些有限，MoE的训练MFU通常比密集模型差得多。在另一个视图中，MoE可以从现成的密集模型中向上循环或转换，而无需从头开始训练。因此，在预算有限的MoE和密集模型之间做出决定时，开发人员可能需要谨慎。

# Transfomer FLOPs 计算

对于一个 A\_mxk \* B\_kxn 的矩阵乘法，FLOPs 是 2𝑚 ×𝑘 ×𝑛 ，其中 2 是因为有乘法，然后加的操作。



假设有 hidden size h, sequence length s, vocabulary size V, and training batch size B



对于一个 Attention Layer，其包括 qkv 三个线性层\+ o 输出层，那么 FLOPs 是 2 \* \(3\* B \*s \* h \*h\+ B \*s \* h \*h\)=8 B s h^2

对于内部的自注意力计算，FLOPs 是 2\*B \* s^2 \* h



对于 MLP 层，一般包括 3 层，up\_proj \+ down\_proj \+ gate\_proj， 以 llama 为例一般中间层的 size 是 hidden size 的 8/3 倍，那么 FLOPs 为 2 \* \( B \*s \* h^2 \* 8/3\)\*3 个=16 B \*s \* h^2



输出层比较好算： 2 B \* s \* h \* V



因此一个标准的不包括 embeding 层的 transformer 层 FLOPs 为 2\*B \* s \* h \* V\+ n\_l \* \(8 B s h^2\+2\*B \* s^2 \* h\+16 B \*s \* h^2\)



然后反向传播是前向的两倍，因此上面的结果要直接乘以 3。



考虑到 checkpoint 会多一次 forward，因此此时要直接乘以 4。

```Python
flops_qkvo_proj = 8 * batch_size * sequence_len * self.hidden_size**2
flops_attn = 4 * batch_size * sequence_len**2 * self.hidden_size * \
    sequence_parallel_size / (int(self.is_casual) + 1)
flops_mlp = 4 * self.mlp_ratio * batch_size * sequence_len * \
    self.hidden_size**2
flops_wo_head = (3 + int(self.use_activation_checkpointing)) * (
    flops_qkvo_proj + flops_attn + flops_mlp) * self.num_layers
flops_head = 3 * 2 * batch_size * sequence_len * self.hidden_size * \
    self.vocab_size
flops_per_iteration = flops_wo_head + flops_head

avg_tflops_per_gpu = flops_per_iteration / 1e12 / (iter_time + 1e-12)
```
